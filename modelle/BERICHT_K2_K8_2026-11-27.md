## K8 - S23DR-2026-Gewinner (LIZENZ: Code Apache-2.0, Gewichte CC-BY-NC-4.0 = NC, NUR TEST)

Code liegt nicht auf GitHub `jskvrna/2026_s23dr` (gibt es nicht; GitHub `jskvrna/WireDiT` = nur Projektseite),
sondern auf Hugging Face `jskvrna/2026_s23dr` (Modellkarte: license cc-by-nc-4.0, research-only).
Hilfsbibliothek `usm3d/tools2025` (hoho2025) Apache-2.0.

Fehlerliste:
- Eingang nicht herstellbar: das Modell braucht je Bild eine HoHo-"Gestalt"-Segmentierung (28 Dachkanten-Klassen: ridge, eave, rake, ...)
  plus ADE20k-Segmentierung plus monokulare Tiefe. Das Gestalt-Segmentiermodell ist nicht oeffentlich (HF-Suche: nichts).
  Lauf daher mit leeren Masken und use_depth=False -> das Netz sieht nur COLMAP-Punkte + Kameras.
- Ergebnis ist Unsinn (Bild angesehen): Turmzone 9/7/7 Ecken je Seed, Kanten kreuz und quer durch den Turm, keine Dachform,
  Seeds widersprechen sich; Stegzone 2/1/4 Ecken, Kanten bis z -13 m (unter der Strasse).
- Zahlen nur der Vollstaendigkeit halber: hoechste Ecke Turmzone z 37,2 / 39,9 / 37,6 m (Traufkasten aus Fotos 37,6-38,1 m) -
  NICHT als Treffer werten, die Kanten dazu sind zufaellig.
- Soll-Werte Steg: masstabelle.json enthaelt KEINE Traufe/First fuer die Bruecke. Gefunden: BRUECKE-LAGE.json First 10,4 m
  (Wolke p95 10,39, DOM1 10,54); die Werte 8,6/9,9 stammen aus messprotokoll/bruecke_lage_1127/einpassung.json
  (p90 8,68, dach_z_p50 9,96, aeltere Einpassung).
- Das Handy-Sparse-Modell hat im Stegstreifen nur ca. 3300 Punkte (Zone 36 x 10 m) - auch mit echter Segmentierung waere der Steg duenn.
